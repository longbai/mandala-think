# MandalaThink 项目格式规范 v2

iPad、iPhone 应用和 Go CLI 都遵循本规范。

每个已保存的格子有一份独立的 YAML，文件名就是格子 ID。父格用「方位 → 子格 ID」关联外围格。展开当前格时，当前格本身就是下一层的中心。点击空位先打开编辑器，首次有效编辑后自动创建并保存该格。

## 1. 项目目录

```text
用户访谈.mprj/
├── project.yaml
├── cells/
│   ├── 7m3k_2w~9p-6t.yaml
│   └── n4-1yqz_6x~3m.yaml
├── assets/
│   └── p8~7w_5k-2dqx.png
└── reminder-links/
    └── 6t9y-3r_q5w~d.yaml
```

| 路径 | 作用 |
|---|---|
| `project.yaml` | 项目身份、格式版本、根格入口及当前项目修订。 |
| `cells/<cell-id>.yaml` | 每个已保存格子一份。去掉扩展名就是 ID。 |
| `assets/` | 随项目保存的图片、视频、音频和其他文件。按需创建，文件名为资源文件 ID 加扩展名。格子的 YAML 使用相对路径引用。 |
| `reminder-links/<action-id>.yaml` | 写入系统提醒事项的执行记录。按需创建，文件名对应行动 ID。 |

日常编辑使用目录形式的 Apple 文档包 `<名称>.mprj`。分享或备份可生成单个 `<名称>.mandalaprj` 文件，内容采用 ZIP 归档，内有一个 `.mprj/` 项目根目录。导入时校验目录或归档结构。首版支持旧 `.mandala` 双向转换及新版分享包导出和重新导入。见第 7 节。

项目内部 ID 统一使用 **13 个随机字符**，省略类型前缀。字符表包含 39 个字符，即 `0123456789abcdefghijklmnopqrstuvwxyz-_~`。格式为 `^[0-9a-z_~-]{13}$`。用系统安全随机源均匀生成，空间为 `39^13`，约 68.7 位随机性。iPad、iPhone 和 Mac 都可以独立离线生成。类型由所在目录或字段确定，ID 的顺序没有业务含义。此处的字符数和字母表是本项目的约定。见 [Nano ID 的自定义字母表说明](https://github.com/ai/nanoid#custom-alphabet-or-size)。

`-`、`_`、`~` 都可以直接用于来源链接。点号留给文件扩展名分隔。项目 ID 在项目库内唯一，格子、行动、资源文件、修订和提交操作按各自在项目中的作用域检查重复。生成时如果发现重名则重新生成。同步后若发现两个独立记录使用同一 ID，则按冲突处理并保留两份内容。格子改名、换位或移动时保留 ID。独立项目副本生成新项目 ID，包内格子之间的引用仍然有效，提醒事项执行记录从空开始。见 [RFC 3986 §2.3](https://www.rfc-editor.org/rfc/rfc3986.html#section-2.3)。

## 2. 项目入口

```yaml
schema_version: 2
project_id: "2xk8m_q~73-4j"
title: "用户访谈"
root_cell_id: "7m3k_2w~9p-6t"
revision: "b4w~8r_36xk-q"
```

| 字段 | 类型与约束 |
|---|---|
| `schema_version` | 必填整数。本文定义的版本为 `2`。 |
| `project_id` | 必填项目 ID。移动或重命名项目包时保留。 |
| `title` | 必填字符串。项目在文件列表中的名称。根格另有自己的正文。 |
| `root_cell_id` | 必填格子 ID。对应的 YAML 必须存在。 |
| `revision` | 必填修订 ID。每次成功提交项目内容后生成新值，用于比对编辑时读到的版本。 |
| `legacy_root_id` | 旧版导入的可选字段。记录原根格目录的编号，类型为非负整数。再导出旧格式时复用。 |
| `legacy_preview_path` | 可选包内封面资源路径，形如 `assets/<文件ID>.<扩展名>`。指向导入旧版项目时保留的封面。 |
| `template` | 可选模板标识，接受 `"five_w"` 或 `"time"`。模板提示属于界面，无需将提示写入空格。 |

读取到更高的格式版本、缺失必填字段或无法校验的文档时，报告问题并保留现有内容，等待打开兼容版本或修复。

## 3. 格子字段与九宫格拓扑

文件 `cells/7m3k_2w~9p-6t.yaml` 的示例：

```yaml
body: "用户访谈\n\n他说：\"先问具体例子\"。\r\n路径示例 C:\\notes\\draft.md\n"
color: "blue"
children:
  top_left: "n4-1yqz_6x~3m"
resources:
  - kind: "image"
    path: "assets/p8~7w_5k-2dqx.png"
    caption: "访谈现场"
  - kind: "video"
    url: "https://media.example.org/interview.mp4"
    title: "示范视频"
  - kind: "link"
    url: "https://example.org/interview-guide"
    title: "访谈指南"
actions:
  - id: "6t9y-3r_q5w~d"
    title: "写出五个访谈问题"
    notes: "从用户最近一次整理笔记的经历问起。"
    due:
      date: "2026-11-20"
      time: "16:30"
      time_zone: "Asia/Shanghai"
```

| 字段 | 类型与约束 |
|---|---|
| `body` | 必填纯文本字符串。格子的唯一正文，允许 `""`，按第 4 节原样保存。九宫格从首条非空行生成预览。 |
| `color` | 可选颜色标记。支持 `red`、`orange`、`yellow`、`green`、`blue`、`purple`、`gray`。省略时使用默认外观。选择颜色会创建并保存未创建的格子。 |
| `children` | 可选映射。键是八个固定方位之一，值是子格 ID。省略或 `{}` 表示当前格还没有已保存的外围格。 |
| `resources` | 可选有序列表。可以混合保存外部链接、图片、视频、音频和普通文件。每项的格式见第 3.1 节。 |
| `actions` | 可选有序列表。每项是第 6 节定义的结构化行动。 |
| `legacy_children` | 仅旧版导入时使用的可选映射。键为来源文件的非标准周边编号字符串，值为子格 ID，在「额外格子」中显示。 |

每格只有一段正文。九宫格优先预览正文的首条非空行。正文为空或只有空白时，格子的第一张包内图片作为九宫格预览，有行动时一并显示第一条行动的名称。详情显示全文一次，行动接在正文后面。正文没有文字时，正文区直接显示包内图片和行动。

格子 YAML 内无需重复记录本格 ID。资源引用、行动与子格均由当前格记录。方位固定如下：

| 左 | 中 | 右 |
|---|---|---|
| `top_left` | `top` | `top_right` |
| `left` | 当前格 | `right` |
| `bottom_left` | `bottom` | `bottom_right` |

`children` 中省略的方位显示为空位。映射的书写顺序不影响屏幕位置。根格没有父格，其余已保存格子都从根可达，且恰好有一个父格。普通子格和额外格子一起接受校验，禁止自引用、循环、重复占位和失效引用。同层换位只改父格的方位映射，跨父格移动须一起提交旧父格、新父格和项目修订。

### 3.1 格子资源

| 字段 | 类型与约束 |
|---|---|
| `kind` | 必填字符串，取值为 `"link"`、`"image"`、`"video"`、`"audio"` 或 `"file"`。 |
| `url` | 外部资源的绝对 HTTP(S) URL，包括网页、远程媒体和可下载文件。保留完整 URL，包括查询参数和片段。 |
| `path` | 包内资源的相对路径，形如 `assets/<文件ID>.<扩展名>`，须指向包内实际文件。 |
| `title` | 可选字符串，资源列表中的显示标题。 |
| `caption` | 可选字符串，资源说明。 |
| `original_filename` | 可选字符串，用于显示导入文件的原名。 |

每项资源必须恰好有一个来源字段，`url` 或 `path`。`link` 使用 `url`。其他类型可以使用任一来源。PDF、压缩包及其他通用文件使用 `file`。视频平台的网页地址可以存为 `link`。直接媒体 URL 可标成相应媒体类型。

从系统文件、照片图库或相机加入的本地媒体和附件在自动保存时复制进 `assets/`，随项目和导出 ZIP 一起携带。外部资源默认只保存 URL，用户打开时才访问。用户若另行选择导入一份本地副本，则用包内路径引用。远程资源离线或失效时仍可查看其标题和地址。App 提供适合对应类型的预览、播放或系统打开入口。

## 4. YAML 和正文保真

项目文件使用 UTF-8 和 YAML 1.2 的受限子集。每个文件一个 YAML 文档。字段类型按本规范解析。禁止重复键、锚点、别名、合并键和自定义标签。写入前校验声明字段及类型。字符串由序列化器写成单个物理行上的双引号标量，日期、时间和 ID 也用引号保存。

| 正文里的原字符 | YAML 中的表示 |
|---|---|
| 双引号 `"` | `\"` |
| 反斜杠 `\` | `\\` |
| LF 换行 | `\n` |
| CRLF 换行 | `\r\n` |
| 单个 CR | `\r` |
| 制表符 | `\t` |
| 两个字面字符「反斜杠、n」 | `\\n` |
| 三个反引号、井号或冒号 | 照常写在引号内。 |

正文按纯文本编辑与显示。形如 `**重点**`、`*提示*` 的字符保持原样。保存时保留开头和末尾的空格、空行、原有换行及 Unicode 字符序列。未编辑的正文直接保留原值。外层 YAML 文件可以统一使用 LF，正文里的 CRLF 仍以 `\r\n` 保留。导入或写入时，应能将解码后的正文转为 UTF-8，与保存前的正文逐字节比对。相同规则适用于标题、附注和行动备注。双引号转义规则见 [YAML 1.2.2 规范 §7.3.1](https://yaml.org/spec/1.2.2/#731-double-quoted-style)。

## 5. 编辑、自动保存与空格

| 用户操作 | 编辑器状态 | 已保存项目的变化 |
|---|---|---|
| 打开一层或展开已有格 | 显示中心和八个方位，空位可点击。 | 无。 |
| 点击某个空白子格 | 打开该方位的临时草稿。 | 无。 |
| 在空位录入有效内容 | 输入短暂停顿后自动校验草稿、父格修订和目标方位。 | 首次提交时分配永久格子 ID，写入格子 YAML，在父格对应方位登记 ID，并更新项目修订。 |
| 编辑已存在的格子 | 输入短暂停顿后自动提交修改。 | 更新已有 YAML，格子 ID 保留。 |
| 返回、切换格子或进入后台 | 立即尝试提交待保存的有效编辑。如果本次无法写完，保留本机待恢复的编辑。 | 提交成功后更新项目。只浏览或仍为空的未创建位置保持原样。 |

空位的首次有效编辑指用户输入了含非空白字符的正文，添加了有效资源，或录入了符合字段规范的行动。模板提示、未完成的输入法组合文字和单独的空白字符不会触发创建。首次提交前清空全部内容时，位置仍为空。已创建或从旧版导入的格子即使内容为空，也保留 ID 和所占方位。确认新建项目时创建根格，导入时可直接创建来源文件中实际存在的格子。

创建子格时，格子文件、父格引用、新增包内资源及新修订作为一次可恢复的提交生效。提交成功前可暂存编辑和资源。写入失败时保留待恢复内容，读取端仍能使用先前的有效项目。再次打开后，先检查目标格位和修订，再恢复未完成的提交。另一台设备先占用目标格位时，保留编辑并让用户选择新位置或处理冲突。iCloud 同步后若出现不完整或冲突的文件集合，保留已知有效版本与待处理内容，等相关文件可用后再重新校验。

未来若 CLI 或 Agent 创建子格，沿用同一条提交语义。读取、预览或生成建议只产生草稿，明确提交后才创建。

## 6. 行动与 Apple 提醒事项

`actions` 是格子内的结构化内容，在阅读和编辑时紧跟正文显示。一条行动可对应一条系统提醒事项。正文中的三反引号、Markdown 复选框和日期都作为文字保存。用户也可以选中文字，执行「转为行动」，再确认字段。

| 字段 | 类型与约束 |
|---|---|
| `id` | 必填行动 ID，在项目内唯一。编辑行动时保留，删除后也不复用。 |
| `title` | 必填、含非空白字符的单行字符串。 |
| `notes` | 可选字符串，支持原样保存换行。默认留空。 |
| `due` | 可选映射。省略表示无截止日期。 |
| `due.date` | 出现 `due` 时必填，格式为 `YYYY-MM-DD`。必须是真实日期。 |
| `due.time` | 可选的 24 小时制时间，格式为 `HH:mm`。省略表示仅指定日期。 |
| `due.time_zone` | 当且仅当有 `time` 时必填，使用 IANA 时区，例如 `Asia/Shanghai`。遇到夏令时导致的重复或不存在时报错，请用户明确时间。 |

操作流程为「选行动 → 预览标题、备注和日期 → 选择可写清单 → 确认创建」。按需请求提醒事项权限。仅有日期时保留日期精度，有时间时按给定时区创建。系统清单在提交时选择，格子内容里保存的是行动本身。到期日与通知闹钟是独立概念。首版由 Apple 提醒事项管理通知、完成状态和重复规则。相关 API 见 [Apple EventKit 创建提醒事项](https://developer.apple.com/documentation/eventkit/creating-events-and-reminders)。

App 在 `reminder-links/<action-id>.yaml` 记录执行结果。使用 `project_id`、`cell_id` 和文件名中的行动 ID 构成来源标识，可写入提醒事项的来源链接。创建时将该链接附在原备注之后，同时写入系统 URL 字段。执行记录内的字段如下。

| 字段 | 类型与约束 |
|---|---|
| `project_id`、`cell_id` | 必填字符串，对应创建时的来源。 |
| `state` | 必填字符串。`"pending"` 表示提交中，`"created"` 表示已创建，`"uncertain"` 表示需要检查系统结果。 |
| `operation_id` | 必填的短 ID。一次提交及其恢复使用同一 ID。 |
| `system_external_id` | 可选字符串。EventKit 的跨设备标识，用于尝试打开已有提醒事项。 |
| `system_item_id` | 可选字符串，保留系统返回的标识。跨设备时可用来源标识核对。 |
| `list_hint` | 可选字符串，保存当时的清单名称，便于回看执行结果。 |

确认操作的设备在提交前记录待处理状态，提交成功后写入创建结果。如果写入结果不明，先查找已有提醒事项，核对后再决定是否重试。当前记录已显示成功时，重复点击展示已有结果。两个离线设备在记录同步前各自确认，仍可能产生重复，需要在同步后核对。导入项目、重开项目或同步文件都不会触发写入提醒事项。项目的交换 ZIP 默认只带行动数据，执行记录按备份场景单独纳入。

## 7. 导入与导出

### 7.1 旧版 MandalArt 格式

导入旧 `.mandala` 时，每个实际源格映射到一个稳定的新 ID。已验证的旧周边编号 `0, 1, 2, 3, 5, 6, 7, 8` 分别映射到左上、上、右上、左、右、左下、下、右下。中心由当前节点承载。根格通过源目录结构识别，原编号保留在 `legacy_root_id`。保留源文件明确存在的空格和额外格。只为界面显示的占位符不会成为正式格子。`Content.txt` 原样进入 `body`，九宫格预览取首条非空行，包内图片及其他附件保存到 `assets/` 并建立 `resources` 引用。原封面资源随根格保留。对无法识别的条目，导入结果列出具体路径及处理情况。

导出旧 `.mandala` 时，按当前格位逆向恢复数字目录和 `Children/` 层级，按原编号写出 `legacy_children` 中的额外格。旧版导入的项目复用所记录的根编号。原生新建项目使用通过旧版 App 导入验证后确定的根编号。已保存的空格须能在重开后恢复，未创建的空位在归档中省略。导出时生成旧版 App 可识别的预览信息。

旧版导出将 `body` 写回单个 `Content.txt`。

旧版导出以通过真机验证的格位、层级、纯文本、封面及图片能力为兼容范围。诸如颜色标记、结构化行动、提醒事项执行记录、不能由旧版识别的资源类型，以及超过旧版可显示数量的同格资源，由兼容预览列出对应格子和处理方式。外链可在用户选择后附入格子正文。用户确认后才生成有降级的副本，源项目保留完整内容。需要完整交换时使用新版 ZIP。

### 7.2 新版文档包与 ZIP

直接打开 `.mprj` 目录时，App 编辑该文档包。导入 `.mandalaprj` 分享文件时，先校验 ZIP 的内部结构与资源，确认目标位置后再还原为 `.mprj` 文档包。常规分享导入为独立副本，分配新项目 ID。显式恢复备份时保留项目身份，如遇同 ID 已存在的项目，先显示冲突并让用户选择保留方式。

新版 ZIP 保留 13 位 ID、层级、格位、正文、包内文件、外部 URL 和行动字段。分享副本默认省略提醒事项执行记录。用户选择备份时可一并纳入。打开或恢复文件不会据此自动创建提醒。

交付归档前校验条目、引用和必要文件。遇到重复条目、路径越出目标目录、缺失资源或解析失败时，保留原文件并给出原因。导出结果另存为新文件，完成校验后才交给系统保存或分享。

## 8. 格式验收

首版验收覆盖以下情形：

1. 只打开九宫格、点空位后离开、只写空白，或在首次提交前清空草稿，均不增加格子文件或父格引用。
2. 任一空位首次有效编辑后自动创建恰好一格。连续编辑、立即返回或切到后台后可恢复最新待保存内容。保存失败时没有半个格子。继续编辑已有格保留 ID。
3. 换位与跨层移动后，子层中心、整个分支和行动来源仍正确。非法引用能定位到具体格子和字段。
4. 正文按纯文本显示。含星号、引号、反斜杠、三反引号、CRLF、制表符、连续空行、末尾换行和 Unicode 组合字符的正文，导入及往返保存后可逐字节核对。
