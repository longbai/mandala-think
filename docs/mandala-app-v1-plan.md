# mandala-think iPad、iPhone 交互与首版开发计划

状态为原生首版开发中。运行方式和当前验收范围见 [原生工程说明](../apps/apple/README.md)。

mandala-think 是 iPad 和 iPhone 共用的原生 App。两端使用同一套项目格式和操作规则。iPad 和展开后的 iPhone Duo 在空间充足时使用并排的九宫格和详情。普通 iPhone、折叠后的 Duo 和窄分屏优先展示当前九宫格。项目日常以文件夹文档包打开，可以放在本机或 iCloud Drive。每个已保存格子有一个 13 位 ID 和一个同名 YAML。格式详见 [mandala-think 项目格式规范 v2](mandala-format-v1.md)。

## 1. 首页与项目入口

首页显示 MandalaThink、「新建」「打开」和项目列表。最近打开的项目排在最前面。点击列表中的项目直接打开，左滑可以删除项目。本机项目移入 MandalaThink 的 Recently Deleted 文件夹，外部项目使用原文件位置提供的废纸篓。「打开」从系统「文件」中选取文档。共享位于已打开项目的工具菜单。从系统「文件」或分享菜单交给 MandalaThink 的文档走同一导入入口。

| 入口 | 流程 |
|---|---|
| 新建项目 | 填写项目名称和中心格正文，选择本机或 iCloud Drive 位置，点「创建项目」后建立项目包和根格。可选择空白九宫格或 5W 提示。 |
| 打开新版文档包 | 打开原位置的 `.mprj`。进入上次浏览的层级，原格已移动时按 ID 定位。格子找不到时返回根层。 |
| 导入旧 `.mandala` | 校验归档，预览封面、示例格位及兼容提示。选择保存位置后转换为一个新版文档包。 |
| 导入新版分享文件 | 打开 `.mandalaprj`，预览项目名称及内容，校验 ZIP 结构与引用，再保存为可编辑的 `.mprj` 文档包。默认为导入独立副本。恢复备份时提供保留项目身份的入口。 |

文件尚未下载时，项目页显示等待下载或重试。格式损坏时，页面显示文件名、原因和能定位的问题。导入过程中可以取消，已发布的项目列表只显示校验并保存成功的项目。

## 2. 九宫格工作区

画布上方可直接切换 3×3 和 9×9，列表视图在工具菜单中。9×9 以当前九宫格为中央区块，周围八个区块各自展开对应格子的下一层。中央区块的外围格与对应区块的中心引用同一份格子。9×9 默认将完整画布适配当前窗口。双指可放大并拖动查看局部，点击「回到全览」恢复完整视图。九个区块以间距和浅底色区分，单格颜色用于突出内容。

### iPad

横屏且空间充足时，九宫格和格子详情并排。左侧项目内结构栏可展开，显示根格和已保存分支。窄窗口、分屏或竖屏时，结构栏收起，详情改用面板。界面随可用宽度变化。

```text
项目名    根层 › 当前分支                      概览 · 导出
┌────────────┬────────────────────┬────────────────────┐
│ 分支结构    │ 当前九宫格          │ 所选格子的详情      │
│ 可收起      │ [左上] [上] [右上]  │ 正文                │
│            │ [ 左 ] [中心] [右]  │ 资源、行动          │
│            │ [左下] [下] [右下]  │ 编辑                │
└────────────┴────────────────────┴────────────────────┘
```

编辑空位时，右侧编辑器标出目标方位，例如「左上格」。有效编辑后开始自动保存，编辑器显示保存状态。在窄窗口中，编辑进入独立面板。外接键盘可以在九格间移动焦点和打开详情。

### iPhone

顶部提供上一层入口，深层路径可直接跳回祖先格。格子内容在九宫格内展示。下面显示完整九宫格，首条非空行作为预览，长行可截断，详情仍显示完整内容。点已有格打开底部详情面板，可拉高阅读。点「编辑」或点空位时进入全屏编辑，顶部显示返回与自动保存状态。九宫格用格子的位置表达方位。窄屏与大字号模式可用列表视图，每个条目会显示方位。旁白在两种视图中都能读出方位。

```text
‹ 上一层     当前中心预览       …
            层级路径

[ 左上 ]   [  上  ]   [ 右上 ]
[  左  ]   [ 中心 ]   [  右  ]
[ 左下 ]   [  下  ]   [ 右下 ]

点已有格：查看详情，详情可拉高
点空白格：进入编辑，有效编辑后自动保存
```

### 两端共用的格子操作

| 操作 | 结果 |
|---|---|
| 点中心格或已有外围格的正文区 | 查看正文、行动和资源。 |
| 点外围格的「展开」 | 将该格作为下一层中心，显示它的八个外围方位。即使尚无子格，也可以进入这一层。 |
| 返回上一层、点路径或从结构概览跳转 | 恢复到目标九宫格。向上返回时可看到刚才进入的分支。 |
| 点空白外围格 | 按所在方位打开临时编辑器。只打开再返回时，原位置保持为空。 |
| 输入或添加有效内容 | 输入停顿后自动保存。首次保存同时创建新格 YAML、提交包内资源，并登记父格方位引用。之后继续编辑同一格。 |
| 返回、切换格子或进入后台 | 立即尝试保存尚未提交的有效编辑。如果本次无法完成，保留本机待恢复的内容。 |
| 交换格位 | iPad 可拖动并看到落点预览。iPhone 可从格子菜单选择目的方位。目标已有格子时预览交换，确认后才提交。原有分支随格子移动。 |
| 移动分支 | 从格子菜单选择新的父格和方位，确认后提交。原格、后代和行动继续使用同一批 ID。 |

已保存但无正文的格子显示为「无正文」并可打开。未创建的位置显示添加入口。语音朗读也要能区分两者，并说明方位、当前选中状态和可展开状态。图标、文字或焦点样式共同表达状态。

有实际改动时显示「保存中」，完成本地提交后显示「已保存」。保存失败保留编辑和资源，用户可重试。如果另一台设备先占用了同一方位，保留当前内容，并提供查看对方内容或改选空位。仅打开空格、只输入空白，或在首次自动提交前清空全部内容，位置都保持未创建。

## 3. 格子编辑、资源和提醒事项

格子编辑器提供一段纯文本正文，按原样保留换行、引号和反斜杠。行动和文字在同一正文区展示，随后是资源。正文没有文字时，正文区直接显示包内图片和行动。九宫格用第一张可显示的图片铺满格子。图片格和文字格的展开按钮都浮在右上角。有行动时，图片底部显示第一条行动的名称。仅有行动时，九宫格预览取第一条行动的名称。选择、焦点和可展开状态各有独立的界面提示。

资源区直接显示「照片图库」「相机」「添加文件」和「添加链接」。可以从图库导入照片或视频，从相机拍摄，或从系统文件选取附件。项目内图片、视频、音频和文件随文档包保存，外部资源在用户打开时访问。点击资源可预览、播放或交给系统打开。离线时仍能看到外部资源名称和地址。

用户可在「行动」区添加一条行动，也可选中正文执行「转为行动」。编辑时可填写标题、备注和可选截止日期。自动保存格子和行动后，App 使用已保存的来源 ID 进入系统提醒事项确认流程。

提醒事项流程为「选行动 → 预览内容 → 选择清单 → 确认创建」。系统权限在需要读取清单或创建提醒时请求。权限拒绝或创建失败时，行动留在原格。成功后可以从格子或详情打开对应的提醒事项。重复确认先核对创建记录，结果不明时先尝试查找已有事项。提醒事项里的来源链接解析项目和格子 ID，格子移动仍能定位。项目未打开时，通过项目库定位并打开项目。随后直接显示来源格详情，并滚动到对应行动。

方法提示从两套小练习起步。5W 以 Who 为中心，在上、左、右、下显示 What、Where、When、Why，四角留给自由联想。进入提示方位后，用户可以参考提示输入自己的内容，有效编辑后自动创建格子。另一套练习演示从年、月、周展开，再回到中心挑选一项行动。

## 4. 项目菜单与两种导出

| 菜单项 | 用户看到的结果 |
|---|---|
| 导出新版分享文件 | 生成单个 `<名称>.mandalaprj` 文件，内部是 ZIP。包括格子 YAML、项目结构、包内资源、外链和行动。选择备份时可以包含提醒事项执行记录。 |
| 导出旧版 MandalArt | 生成 `<名称>.mandala`。导出前显示旧版兼容情况，包含哪些内容，以及哪些内容可选写成文本链接或需要省略。 |
| 保存到「文件」或分享 | 选择目标位置或分享对象。重复文件名走系统的另存或替换选择。 |

旧格式导入和导出均属于原生首版。旧格式以真机验证过的格位、层级、空格、文本及图片为兼容范围。无法表示的行动、提醒事项记录、视频等内容，在导出预览中按格列出。导出有降级的副本时由用户确认。新版 ZIP 提供含这些内容的交换副本。两个导出入口都独立生成归档。日常打开、编辑和同步使用原位置的文档包。

导出预览基于最近一次成功保存的项目修订。开始导出时若有待保存编辑，先尝试完成本地提交。如果提交失败，页面提示错误并返回编辑，方便处理后重新导出。

## 5. 本地保存与 iCloud 状态

App 区分「保存中」「已保存」「等待同步」「发现冲突」「保存失败」。本地自动保存完成后即可继续编辑，iCloud 同步状态单独显示。当目标方位、子格引用或文件同步不完整时，先保留最近的有效版本。冲突页显示受影响的格子，允许查看双方内容、选择保留一版或另存。用户在哪台设备确认，哪台设备就执行提醒事项创建。另一台设备收到同步结果后可以显示对应状态。

App 与未来 CLI 使用同一套项目模型、旧格式转换规则和校验语义。现有浏览器阅读器已整体迁移至 `apps/web-reader/`，保留独立 Git 及原托管配置，静态入口位于 `dist/index.html`。

## 6. 界面语言

首版包含简体中文、日语、韩语和英语。默认跟随系统，用户也可以用地球菜单即时切换界面语言。按钮、格位、模板、文件错误、导出兼容性与提醒事项说明同步切换。项目现有文字与附件保留原语言。

## 7. 首版开发顺序

| 阶段 | 工作 | 验收条件 |
|---|---|---|
| 1. 文件基线与原型 | 用目录内原版和中文版做旧格式测试样本。确认原版 MandalArt 真机和系统版本，验证根编号、图片、封面、实际空格及非标准子格。完成新版文档包、13 位 ID、字段校验和归档的基础设计验证。安排浏览器阅读器独立目录迁移。 | 有明确的旧格式读写验收表。当前浏览器阅读器可独立运行。对于暂未在旧 App 验证的格式行为，先记录结果和待验证项。 |
| 2. iPad 导入与编辑 | 建立项目列表、系统文件入口、iPad 九宫格、格子详情、纯文本编辑、自动保存、分支导航和资源。接入旧格式导入。 | iPad 可打开样本。点空位再返回无新增文件。首次有效编辑自动创建一格。继续编辑保留 ID。分支展开、移位与重开后，格位和正文保持一致。 |
| 3. iPhone 和跨设备保存 | 完成紧凑布局、详情面板、全屏编辑、快速记录和大字号操作。接入 iCloud Drive、离线保存和冲突展示。 | iPhone 可执行 iPad 同样的核心操作。两端真机能接续打开、离线编辑，并在发生同格冲突时找回双方内容。四种语言均覆盖主要界面和保存反馈。 |
| 4. 双向格式、ZIP 与提醒事项 | 完成旧格式导出和兼容预览、新版 ZIP 导出和重新导入。完成两套方法练习及提醒事项创建。 | 原版 MandalArt 真机打开导出的旧文件，再导回新 App 验证格式。新版 ZIP 往返保留格子 ID、正文、资源与行动。提醒事项可创建、重复确认、失败重试和返回来源格。 |
| 5. 原生首版验收 | 用实际项目走一遍新建、导入旧书、多层编辑、两端接续、生成提醒和分别导出。覆盖损坏文件、保存中断、缺失媒体和同步冲突。 | iPad 和 iPhone 真机同时通过。旧版回导兼容结论以真机成绩为准，仅用现有解析器通过属于初步检查。 |
| 6. macOS CLI | 原生首版验收后再做。先支持读取、校验和旧格式／新版 ZIP 转换，再支持版本检查、预览和显式提交局部编辑。 | CLI 输出可由 App 重开。模拟提交与失败的提交不创建格子，成功提交保留格位和引用。 |
| 7. Agent Skill | CLI 稳定后再做。Codex 或 DeepSeek harness 通过 CLI 读取指定项目、按九宫格方法提出问题、生成行动和提交授权修改。 | Agent 的草稿可由 iPad／iPhone 继续打开编辑。Agent 的行动草稿仍从 App 确认写入提醒事项。 |

旧格式真机验证优先使用 `memology.mandala`（根编号 1）、`kansei.mandala`（根编号 5）和 `seikou.mandala`（根编号 9），再用六份中文版复测。非标准子格另建专项样本。原版 App 的测试设备及可运行版本在阶段 1 确认，作为旧格式导出验收的前置条件。
